## 2. OSM 公開 GPS 軌跡驗證 → **資料不足，停下**

| 項目 | 結果 |
|---|---|
| 你給的全臺北 bbox（121.45,24.96,121.67,25.21）page 0–4 | 5 頁全部 **HTTP 503 first byte timeout**（API 本身正常，`/api/capabilities` 200）：範圍太大，伺服器來不及回應，必須切成小格 |
| 改抓 6 個 0.005°（約 500 m）小格各 page 0：大安森林公園、大佳河濱、中正紀念堂、內湖、天母、信義 | 5 格成功、大佳河濱 503；共 25,000 點、226 條軌跡 |
| 有時間戳的點 | 25,000 / 25,000（100%） |
| 軌跡性質 | 描述欄大量是 dragonpilot／sunnypilot（車用輔助駕駛行車紀錄）；非車用軌跡的速度多在 30–60 km/h |
| 跑步段落（6–15 km/h、點距 ≤ 30 秒、連續 ≥ 2 分鐘且 ≥ 200 m，已排除 pilot 軌跡） | **0 段** |
| 軌跡年份 | 2018–2026，2023 後占多數 |
| 對照 11/3 舊專案 | 大安森林公園旁 51 頁、259,870 點、782 條軌跡，也是 0 段 |

結論：OSM 公開軌跡以行車為主，6–15 km/h 也分不出跑步、自行車與塞車，**不能代表臺北跑者**。照你的備案：改用「公園 + 河濱步道」定義熱門跑步區域，之後換 Strava Metro。注意公園基本資料幾乎沒有河濱公園，河濱步道要從 OSM 路網（例如 `leisure=park`、河濱 `highway=footway/cycleway`）補。

## 3. 這些資料能不能支持情境切換？

| 情境 | 能不能 | 依據 |
|---|---|---|
| 時段（清晨 5–7、上班 7–9、中午 11–13、下班 17–19、夜間 19–22） | ✅ | 逐時資料，每個小時都有約 4,350 筆；每站每時段約 700–1,100 小時 |
| 平日／假日 | ✅（有一個缺口） | 週一–五 / 週六日可直接算；要把國定假日、補班日算對，**還缺 2025 年（114 年）辦公日曆** |
| 季節（冬 12–2、春 3–5、夏 6–8、秋 9–11） | ✅ 但每季只有一年 | 2025-11 屬秋季、2025-12–2026-02 為冬季；秋季由 2025-11 + 2026-09、10 組成（跨兩年）。季 × 假日 × 時段 × 站最細格約 50 小時，可算平均但不宜過度解讀 |
| 尖峰 vs 離峰 | ✅ | 同上；交通站 3 站可對照一般站 |
| 各**行政區** AQI | ⚠️ 需要推估 | 12 站只落在 9 個區；**北投、松山、萬華沒有測站**；中山、南港、士林各有 2 站。各區數值必須用內插或最近站推估，畫面要標示 |
| 「上下班車潮造成的空污」 | ⚠️ 只能間接 | 沒有歷史車流量；只能用 NO2／CO 的時段差 + 交通站 vs 一般站對照；電信旅次是 2020 年、行政區粒度、時段切法不同 |
| 路線：空品／樹蔭／公園／遠離車流 | ✅ 可做（加分） | 空品＝測站內插到路段；樹蔭＝17.5 萬棵樹（TWD97 轉 WGS84）；公園＝812 點 + 面積；車流＝OSM 道路等級（代理變數，不是實際車流） |
| 氣象（風、雨） | ❌ | 466920 缺少 |
